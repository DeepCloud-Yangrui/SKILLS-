# 第一视角分镜自检

## 何时使用

当用户提供一组已有分镜（通常来自 first-person-ai-story 阶段五产出，或独立生成的分镜脚本），要求检查其质量时使用。本Skill**只评价，不创作**——不产出新分镜、不改写故事、不生成生图提示词。

## 评价原则

1. **只报问题，不打分。** 分数掩盖细节，问题清单才能改。
2. **区分合规与质量。** "违反规则"和"读起来不好"是两类问题，分开列。
3. **每条问题必须定位到具体画面序号。** 禁止"整体节奏偏慢"这类无定位的评价。
4. **每条问题必须给修改方向，但不代写。** 说"建议拆成两画面"，不说"应该改成……"。
5. **不确定就标为"待确认"，不强行判定。** 有些问题取决于创作意图，评价者不应替作者决定。

## 输入要求

**用户只需提供分镜脚本。视觉圣经和异常升级表由本Skill自动从分镜所在目录查找。**

### 查找逻辑

1. **确定分镜文件所在目录**：
   - 若用户给了文件路径，取该文件所在目录
   - 若用户只贴了分镜内容，向用户询问作品名或分镜文件路径
2. **在同级目录查找两个文件**：
   - `视觉圣经.md`
   - `异常升级表.md`
3. **读取并核对**：
   - 读到了 → 直接使用，并在报告"输入完整性"一栏标注来源路径
   - 没读到 → 停下来问用户，不要凭分镜内容反推

### 目录约定

本Skill假定项目结构为：

```text
<项目根>/<作品名>/
├── 分镜.md ← 用户提供
├── 视觉圣经.md ← 自动查找
├── 异常升级表.md ← 自动查找
└── 故事正文.md ← 不读取
```

若实际目录结构不同，按实际查找；找不到就询问用户，不要猜测。

## 检查维度一：与创作规范的一致性

对照 first-person-ai-story 的核心规则，逐条核对：

### 1. 异常升级

- [ ] 是否跳级？（第1级直接到第5级）
- [ ] 是否有降级？（第5级回落到第4级）
- [ ] 每一级的"观众感受"是否与设计一致？
- [ ] 七级是否全部覆盖，还是有级缺失？

### 2. 一图一信息

- [ ] 是否存在单张画面塞入多个核心信息？
- [ ] 每张画面是否"回答一个问题，同时制造下一个问题"？
- [ ] 是否有画面只承担气氛、不推进信息？（若为蓄力画面，标记为"待确认"）

### 3. 视角使用

- [ ] 第一视角是否用于"体验"（探索、打开、查看、进入）？
- [ ] 第三视角是否仅用于"交代"（时代、全貌、人物关系、回忆）？
- [ ] 是否有视角滥用？（用第三视角写本该体验的内容）

### 4. 手机随拍感

- [ ] 画面描述是否过于"完美"？（构图精致、光线均匀、人物摆拍）
- [ ] 是否有具体的不完美细节？（歪斜、噪点、杂物、光线不均）

### 5. 证据式叙事

- [ ] 是否有画面直接"告诉"观众结论，而非展示证据？
- [ ] 关键信息是否通过物品、文件、痕迹呈现？

---

## 检查维度二：分镜自身的可执行性

这一维度检查分镜作为"下游生图输入"的质量：

### 6. 画面描述的具体性

- [ ] 是否写清了主体、动作、环境、光线？
- [ ] 是否包含生图必需但可能被遗漏的要素？（时间、天气、景别）
- [ ] 是否存在歧义描述？（"一些东西"、"某种感觉"）

### 7. 画面之间的区分度

- [ ] 是否有两张画面描述高度相似、可能生成雷同图？
- [ ] 如果同机位重复（如"假发又回来了"），是否在描述中明确标注了差异点？

### 8. 视角的可视化

- [ ] 第一视角画面，是否写清了"拍摄者"的姿势和位置？
- [ ] 第三视角画面，是否写清了机位在哪？

### 9. 信息密度

- [ ] 是否有画面描述过长、含多个视觉焦点？
- [ ] 单张画面的视觉焦点是否唯一？

---

## 检查维度三：跨画面的视觉连续性

逐项核对视觉圣经：

### 10. 人物一致性

- [ ] 主角的外貌、服装是否跨画面一致？
- [ ] "他"的呈现是否始终为剪影/轮廓/手，没有意外露脸？
- [ ] 配角（如大妈）的外貌是否与圣经一致？

### 11. 场景一致性

- [ ] 房间结构（门窗位置、家具布局）是否跨画面一致？
- [ ] 场景切换（如从出租屋到宿舍）是否在圣经中有定义？
- [ ] 光线基调是否与场景设定一致？

### 12. 道具一致性

- [ ] 关键道具（如假发、睡衣、书）的状态变化是否有链条可循？
- [ ] 道具的位置、外观是否前后矛盾？
- [ ] 是否有画面用到圣经未定义的道具？

### 13. 视觉图腾

- [ ] 图腾是否在首尾出现？
- [ ] 图腾的出现是否自然，而非硬塞？

### 14. 伏笔的视觉化

- [ ] 阶段一列出的"真相痕迹"是否都出现在分镜中？
- [ ] 每一条痕迹是否能在后期被"重新解释"？

## 输出格式

按以下结构输出报告：

```text
# 分镜自检报告

## 一、输入完整性
- 分镜脚本：[完整 / 缺失 X 项]
- 视觉圣经：[自动读取自 <路径> / 未找到]
- 异常升级表：[自动读取自 <路径> / 未找到]

## 二、合规性问题
| 序号 | 画面 | 违规类型 | 严重程度 | 修改方向 |
|:---|:---|:---|:---|:---|
| 1 | 图14→15 | 异常降级 | 中 | 在图15补入第5级证据，或调整图14信息量 |

## 三、可执行性问题
| 序号 | 画面 | 问题 | 严重程度 | 修改方向 |
|:---|:---|:---|:---|:---|

## 四、视觉连续性问题
| 序号 | 画面 | 问题 | 严重程度 | 修改方向 |
|:---|:---|:---|:---|:---|

## 五、待确认项
（取决于创作意图、无法自动判定的问题）

## 六、总览
- 合规性问题：X 项（严重 X / 中 X / 轻微 X）
- 可执行性问题：X 项
- 视觉连续性问题：X 项
- 待确认项：X 项
- 最需要优先处理的三项：1. ___ 2. ___ 3. ___
```

## 严重程度定义

| 级别 | 定义 | 处理建议 |
|:---|:---|:---|
| **严重** | 破坏叙事逻辑或视觉连续性，观众会发现 | 必须修改 |
| **中** | 削弱效果但不致命 | 建议修改 |
| **轻微** | 优化项，不影响理解 | 可选修改 |
| **待确认** | 取决于创作意图，无法自动判定 | 由作者决定 |

## 禁止事项

- ❌ 不产出新分镜、不代写修改后的画面描述
- ❌ 不打分（如"8/10"），只报问题
- ❌ 不做无定位的评价（"整体不错"、"节奏偏慢"）
- ❌ 不检查故事正文——那是 first-person-ai-story 阶段六的事
- ❌ 不检查生图提示词——那是另一个下游 Skill 的事
- ❌ 不修改视觉圣经——只报告"圣经未定义的元素"，由作者决定是否补入
- ❌ 不向用户重复索取视觉圣经和异常升级表——先自己从目录找，找不到再问
